# 学习方式模板（`2.<主题>学习方式.md`）

学习方式文档定义学习流程、文件组织、实操规则和复习规则。每次学习前都要读它。
（命名也可叫 `2.<主题>学习Prompt.md`，二者等价；本项目 Python/AI 用「学习方式」，MySQL/Redis 用「学习Prompt」。统一推荐用「学习方式」。）

## 文档骨架

```
# <主题> 学习方式

> 本文档定义了学习流程和文件组织规范，请在每次学习开始时读取本文档。
> 推荐使用顺序：读取 1.<主题>学习路线.md、本文档、3.学习进度.md、4.章节复习记录.md，然后开始学习。

---

## 一、学习流程（5 步循环）
## 二、章节文件结构规范
## 三、README.md 格式规范        （可并入二）
## 四、学习进度.md 格式规范
## 五、章节复习记录.md 格式规范
## 六、<主题>学习特别约定         （按 Demo 介质注入，见末尾）
## 七、关键约定                   （表格汇总）
```

## 一、学习流程（5 步循环）——所有主题通用

```markdown
## 一、学习流程（5 步循环）

每个章节按以下步骤推进。章节顺序、阶段划分和知识点以 `1.<主题>学习路线.md` 为准。

### 第 1 步：生成理论文档
- 根据学习路线上的章节，生成该章节的技术讲解文件（.md 格式）
- 每个知识点一个独立的 .md 文件
- （编程类）同时生成 `本章节面试常考内容.md`，放在所有理论知识点文件之后
- 执行方式：当本章节包含多个知识点时，主 agent 先根据学习路线判断知识点之间是否存在前置依赖，并按依赖关系分层拆分任务；同一层中相互独立的知识点优先调用多个子 agent 并行生成，各层之间按前置关系顺序推进。主 agent 负责统一命名、提供共享背景、检查术语一致性、格式规范与汇总验收。只有单个知识点、知识点强依赖无法拆分，或当前环境不支持并行 agent 时，才串行生成。

### 第 2 步：生成 Demo
- 为每个理论知识点创建对应的 Demo（文件类型见特别约定）
- 所有 Demo 放在章节目录下的 `demo/` 文件夹中
- 包含一个 `README.md`，说明学习顺序、每个 Demo 的作用、与理论文档的对应关系

### 第 3 步：学习理论知识
- 阅读理论文档，遇到不理解的内容直接问 AI
- AI 讲解后，将讲解内容补充到对应理论文档的相关位置（不另起文件，加到原文对应位置）

### 第 4 步：实操 Demo
- 阅读 Demo，遇到不理解的地方直接问 AI
- AI 讲解后，将讲解写到代码旁边（脚本写成注释 / .md Demo 写成紧贴命令的文本）
- 理解后运行 Demo，观察输出结果

### 第 5 步：更新进度 & 安排复习
- 本章节学习完成后，告诉 AI"更新学习进度"
- AI 将学习内容、核心理解、产出文件记录到 `3.学习进度.md`
- 下次学习时，先读取 `3.学习进度.md`，再说"开始学习"即可继续

**复习提醒（每章完成后必做）：**
完成进度更新后，AI 自动提示复习本章所有理论 .md、demo/README.md 及所有 Demo，
并在 `4.章节复习记录.md` 中将本章节所有文档标记为未复习，等待使用者确认。

**复习记录更新规则：**
使用者说"已经复习了第 N 章"后，AI 将该章节所有行更新为已复习，记录复习日期（YYYY-MM-DD）。
```

## 二、章节文件结构规范

```markdown
N.章节名称/
├── 1.知识点A.md              # 理论讲解
├── 2.知识点B.md              # 理论讲解
├── 3.知识点C.md              # 理论讲解
├── 4.本章节面试常考内容.md    # 仅编程类：编号紧接最后一个理论知识点
└── demo/
    ├── README.md             # 学习顺序 + Demo 说明 + 理论对应关系
    ├── 1_demo_a.<ext>
    ├── 2_demo_b.<ext>
    └── 3_demo_c.<ext>
```

`<ext>` 取 SKILL.md 第 2 步判定的 Demo 文件类型。

## 三、README.md 格式规范（demo 目录索引）

每个 Demo 这样描述：

```markdown
### Demo N: 标题（一句话定位）
**文件**: `文件名.<ext>`

这个 Demo 做什么、演示什么核心概念（2-3 句话）
```

README 末尾必含：**对应理论文档**（表格映射 Demo ↔ 理论 .md）、**核心要点**（总结本章关键概念）。
SQL / CLI 类还需「执行前准备」「推荐执行顺序」「注意事项」。

## 四、学习进度.md 格式规范

```markdown
## 第N章：章节名称

- 学习方向：<主题>
- 学习状态：已完成
- 完成日期：YYYY-MM-DD

### 本章学习内容
- 知识点A / 知识点B / 知识点C

### 核心理解
- 用自己的话总结本章最重要的理解
- 记录易混淆 / 易踩坑的地方
- 记录关键命令/SQL/语法、底层原理、面试高频点

### 产出文件
- `N.章节名称/1.知识点A.md`
- `N.章节名称/demo/README.md`
- `N.章节名称/demo/1_demo_a.<ext>`
```

## 五、章节复习记录.md 格式规范

```markdown
## 第N章：章节名称

| 文件 | 类型 | 复习状态 | 复习日期 |
|------|------|----------|----------|
| 1.知识点A.md | 理论 | 未复习 | - |
| demo/README.md | Demo | 未复习 | - |
| demo/1_demo_a.<ext> | Demo | 未复习 | - |
```

确认复习后整章更新为「已复习」+ 当天日期。

## 七、关键约定（结尾表格）

```markdown
| 约定 | 说明 |
|------|------|
| 学习路线 | 只使用 `1.<主题>学习路线.md` |
| 理论讲解加到原文旁边 | 不新建解释文件，直接补充到对应知识点的位置 |
| Demo 讲解 | 脚本写成代码注释 / .md Demo 写成紧贴命令的文本 |
| 进度记录在 3.学习进度.md | 每章学完后更新 |
| 复习记录在 4.章节复习记录.md | 每章完成后写入，确认后更新为已复习 |
```

# 六、特别约定——按 Demo 介质二选一注入

根据 SKILL.md 第 2 步判定的介质，把对应一段写进「六、<主题>学习特别约定」。

## A. 可运行脚本类（Python / Java / Go / JS / 框架等）

- Demo 是可独立运行的脚本，每个尽量自包含、`main` 里直接演示、`print`/日志打印结果便于观察。
- Demo 讲解一律写成**代码注释**，紧贴对应代码行，不另起文件。
- 编程类额外产出 `本章节面试常考内容.md`，编号紧接最后一个理论知识点。
- 涉及外部服务/密钥时，统一用变量（如 `API_KEY`、`BASE_URL`、`MODEL`）占位，学习者自填，不要硬编码真实密钥。
- README 标注每个 Demo 是否需要额外依赖 / 配置。

## B. SQL / 数据库类

- Demo 优先用 `.sql` 文件，必要时配 `.md` 说明（不能替代 SQL）。
- **一律使用测试库**（如 `CREATE DATABASE IF NOT EXISTS <主题>_study`），禁止在生产库执行。
- **危险 SQL 必须在 `--` 注释里写明风险**：`DROP`、`TRUNCATE`、无 `WHERE` 的 `UPDATE`/`DELETE`、大批量 `INSERT`、显式加锁、改全局配置。
- SQL 写成**可重复执行**形式（先 `DROP TABLE IF EXISTS` 再建）。
- 事务/锁/隔离级别/MVCC/主从 等多会话实验：用多个文件区分会话（`1_session_a.sql`、`2_session_b.sql`），写清每步在哪个会话执行、预期现象、原因。
- 索引/优化/分页 等章节：Demo 必须含「优化前 SQL + `EXPLAIN`」「优化后 SQL + `EXPLAIN`」对比。

## C. CLI / 命令行工具类（Redis / Linux / Docker / Git 等）

- Demo **统一用 `.md` 图文文档**（不是可直接跑的脚本），学习者从中复制代码块到终端执行。
- 代码块按语言标注：命令用 ` ```bash `/` ```shell `，纯工具命令用专属标识（如 ` ```redis `），脚本用 ` ```lua `，配置用 ` ```conf `。
- 每条命令都要写：命令本身（代码块、可复制）+ **预期输出** + **讲解**（为什么是这个结果，底层机制）。
- Demo `.md` 推荐结构：场景描述 → 环境准备 → 命令演示（逐条+预期输出+讲解）→ 观察验证 → 变量实验 → 清理 → 核心要点。
- **危险命令用 `> ⚠️ **危险**：…` 引用块明显提示**（如 Redis 的 `FLUSHALL`/`KEYS *`、Linux 的 `rm -rf`）。
- 多客户端/多终端实验用三级标题分会话：`### 客户端 A（终端 1）`、`### 客户端 B（终端 2）`，写出每步预期现象。
- 一律使用测试环境（如 Redis `SELECT 15` + 统一 key 前缀 `study:`），禁止在生产执行。
- 性能/原理章节按「操作前 → 观察 → 操作 → 再观察」组织，配观察命令对比。

## D. 纯理论 / 概念类

- Demo 用 `.md` 图文文档，含示意图（ASCII 或 Mermaid）、伪代码、类比例子。
- 不强求可运行；重点是把抽象概念讲透、配可视化。

# 可选：`5.建议（必看）.md`（环境搭建）

仅当主题需要特殊环境（数据库、容器、虚拟机、CLI 工具安装）时生成。内容是**给学习者看的环境搭建建议**，开头标注「AI 请忽略此文档」。包含：推荐学习环境方案（可给 1-2 种，注明推荐哪种及理由）、逐步搭建教程、安装命令、踩坑提醒。参考本项目 `Mysql/5.建议（必看）.md`。
