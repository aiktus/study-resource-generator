# 进度与复习记录模板（`3.学习进度.md` / `4.章节复习记录.md`）

这两个文件在生成脚手架时**只写标题和一句说明**，正文随每章学习进展由 5 步循环追加。本项目现有文件夹里它们初始就是空的（只有文件存在）。

## 理论 .md 的 frontmatter 字段（第一档默认，所有主题必带）

每个理论知识点 `.md` 头部统一带：

```yaml
---
status: 未学        # 未学 / 已学 / 复习中
stage: 2            # 阶段号
importance: 3       # 1-3，对应学习路线的 ⭐ 数
review: []          # 复习日期数组，确认复习后追加，如 [2026-08-15]
tags: []            # 可选，如 [<主题>/第2章, 面试高频]
---
```

第 5 步更新进度时同步刷新 `status`；知识点生成时根据学习路线填写 `stage` 和 `importance`；复习确认后追加 `review` 日期。`tags` 为可选字段，只在确实有助于筛选时添加。非 Obsidian 环境下 frontmatter 只是文件头元数据，无害。

## `3.学习进度.md` 初始内容

```markdown
# <主题> 学习进度

> 每学完一章，在此追加记录。格式见 `2.<主题>学习方式.md` 第四节。
```

学习推进后，每章追加一段（格式见 method-template 第四节）：

```markdown
## 第N章：章节名称

- 学习方向：<主题>
- 学习状态：已完成
- 完成日期：YYYY-MM-DD

### 本章学习内容
- 知识点A
- 知识点B

### 核心理解
- 用自己的话总结本章最重要的理解
- 易混淆 / 易踩坑的点
- 关键命令/SQL/语法、底层原理、面试高频点

### 产出文件
- `N.章节名称/1.知识点A.md`
- `N.章节名称/demo/README.md`
- `N.章节名称/demo/1_demo_a.<ext>`
```

## `4.章节复习记录.md` 初始内容

```markdown
# <主题> 章节复习记录

> 每章完成后由 AI 写入本章所有需复习文件，初始为「未复习」。
> 使用者说「已经复习了第 N 章」后，AI 将该章整体更新为「已复习」+ 当天日期（YYYY-MM-DD）。
```

学习推进后，每章追加一张表（初始全「未复习」）：

```markdown
## 第N章：章节名称

| 文件 | 类型 | 复习状态 | 复习日期 |
|------|------|----------|----------|
| 1.知识点A.md | 理论 | 未复习 | - |
| 2.知识点B.md | 理论 | 未复习 | - |
| demo/README.md | Demo | 未复习 | - |
| demo/1_demo_a.<ext> | Demo | 未复习 | - |
```

确认复习后整章每行更新为：

```markdown
| 1.知识点A.md | 理论 | 已复习 | 2026-05-29 |
```

## 注意

- `<ext>` 用本主题判定的 Demo 文件后缀。
- 编程类的章节复习表要额外列入 `本章节面试常考内容.md`（类型记为「面试」）。
- 复习状态本项目有两种写法：纯文字「未复习/已复习」（MySQL、Redis）或带符号「❌ 未复习 / ✅ 已复习」（Python）。任选其一，全主题统一即可。
